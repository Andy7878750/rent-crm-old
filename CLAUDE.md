# Расчётка (rent-crm)

@AGENTS.md

CRM для арендодателя: коммунальные платежи арендаторов. ТЗ — Claude Docs «ТЗ: CRM для арендодателя (пилот, Россия)», макет — артефакт «Расчётка — главный экран».

## Стек
- Next.js 16 (App Router, `cacheComponents: false` — всё приложение за логином и динамическое), React 19, TypeScript, Tailwind 4.
- PostgreSQL + Drizzle ORM (`src/db/schema.ts`, миграции в `drizzle/`).
- Вход: свои сессии (scrypt + токен в httpOnly cookie, в базе хеш), `src/lib/auth/`.
- Модуль расчёта без зависимостей: `src/lib/calc/` — главный источник правды по суммам.

## Правила
- Каждое серверное действие само проверяет, что объект/услуга/арендатор принадлежит аккаунту пользователя.
- Суммы: строка округляется до копеек, итог = сумма строк. Любое изменение расчёта — сначала тест в `tests/calc.test.ts`.
- Тексты интерфейса — по-русски, термины как в ТЗ («Ввод данных», «Счета на помещение», «Остаётся на вас»).

## Как работаем с владельцем
- Одна задача — один чат. Коротко: план → «да» → делаем прямо в сайте, в его дизайне (без отдельных макетов, если не попросит).
- Дизайн не меняем без согласия: палитра #34495e + терракота, Golos Text, тёмная полоса + светлое меню, окна закрываются только крестиком.
- В main — только после «выкладывай»: push в main сразу выкладывает на сервер (миграции применяются, перед ними копия базы в /var/backups/rent-crm).

## Выложено 04.11.2026: окно-конструктор квитанции (коммит 8b4ff8e, ветка `receipt-lines` слита в main)
Окно привязки квитанции проработано в чате; макет — `docs/mockups/receipt-constructor-mockup.html` (в нём «Сверка 10 примеров»).
- Квитанция = строки (количество × тариф): `services.config` (jsonb), расчёт — `src/lib/calc/lines.ts`, подключён в `engine.ts`; старые квитанции без config считаются по тарифам, как раньше.
- Хранение месяца: главная сумма (`config.billKey`) — в `object_bills`, остальное — `receipt_values`; показания — `readings`, zone = ключ строки ('' — первая, 'day'/'night', 'L2'…).
- Окно `objects/[id]/receipt` — только настройка; суммы и показания месяца — в рамках на странице объекта (`receipt-frame.tsx`).
- Старая квитанция при открытии раскладывается по строкам (`fromLegacy` в `src/lib/receipt-config.ts`) и переходит на них после «Сохранить».
- Отступления от макета: «+ Строка / Доплата / Скидка / Подогрев» и «Остаток квитанции» (в макете не было способа их задать); можно снять всех в «Платят» — тогда квитанция на вас (капремонт).
- «Поровну» делит только между теми, кто платит (в макете — на всех; иначе мусор у одного арендатора делился пополам).
- Миграция 0008 (только добавляет таблицу и колонку). Тесты (`tests/lines.test.ts`), lint и сборка проходят.
- Проверено в браузере на локальной базе: все 7 квитанций примера «Королёва 61» переведены на строки, итоги совпали со старыми до копейки; ввод сумм и показаний в рамках пересчитывает счёт.
- Старые квитанции на сервере переходят на строки, когда владелец открывает их и нажимает «Сохранить».

## Локальный запуск (ноутбук, 04.11.2026)
- PostgreSQL 18 локально, база/пользователь `rentcrm`/`rentcrm`; `.env` — по `.env.example` + `REGISTRATION_OPEN=1` (там же тестовый вход).
- `npm run dev` в Next 16.4 не открывает страницы входа («page files do not match any complete route» — строгая проверка маршрутов из-за `(app)/@modal`); сборка проходит. Для проверки: `npm run build && npm start` (`.claude/launch.json` → rent-crm-prod).
- На этом компьютере в Windows не работает SChannel (winget, окно входа Git): git настроен на `http.sslBackend openssl`, вход в GitHub — токеном.
